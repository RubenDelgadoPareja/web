## Why

The portfolio is evolving quickly, but there is no formal record that connects each delivered change to its intent, scope, and completion status. We need a lightweight process so every web update can be tracked end-to-end and reviewed later.

## What Changes

- Introduce an OpenSpec-first workflow for all meaningful website updates.
- Define a mandatory proposal/design/spec/tasks artifact set for each change.
- Add a release journal process that summarizes completed changes and links to OpenSpec artifacts.
- Establish a Definition of Done that requires updating tasks and archiving the change.

## Capabilities

### New Capabilities
- `portfolio-change-tracking`: Define the required lifecycle and artifacts to track website changes from proposal to archive.
- `portfolio-release-journal`: Define how completed website changes are summarized for historical traceability.

### Modified Capabilities
- None.

## Impact

- Affected systems: OpenSpec workflow under `openspec/changes/` and `openspec/specs/`.
- Affected process: planning, implementation tracking, and release documentation.
- No runtime impact on production website behavior.
